# トッタリー

トランプ52枚を駒にした、2人用のカード×陣取りバトル。
1台の端末で交互に指すか、合言葉でルームを作ってオンラインで対戦する。CPU戦もある。

現在の版: **v49 (アカウント・布陣ボーナス・記録の再生・BGM)**

手で確かめる手順は [動作確認.md](動作確認.md) にまとめてある。
変更を入れたら、上から順に見ていけばよい。

## ビルド

```
npm install
npm run build     # index.html を生成
```

`index.html` は React もカード画像96枚も data URI で内包した単一ファイルで、
これ1つを置けば動く。サーバー側の設定には依存しない。

## 配信 (Netlify)

GitHub の `main` へ push すると、Netlify が [netlify.toml](netlify.toml) のとおりに組み立てて配信する。

```
command = "npm ci && node build.mjs"
publish = "dist"
```

`node build.mjs` は `index.html` と `dist/index.html` の両方を書き出す。
公開されるのは `dist/` だけなので、`src/` や `tools/` は配らない。
`dist/` は毎回作り直されるので git には入れていない。

### 配信されたものが手元と同じか確かめる

Netlify は `</html>` のあとに計測用のスクリプトを1行足す。
ファイル全体のハッシュを比べると必ず食い違うので、そこまでで切って比べる。

```
diff <(curl -s https://iridescent-pothos-77fe76.netlify.app/ | sed -n '1,/<\/html>/p') \
     <(sed -n '1,/<\/html>/p' dist/index.html)
```

オンライン対戦は Realtime Database をクライアントから直接叩いている。
配信先では通信の制限がないので、**そのまま対戦できる**。
ただし**データベース側のセキュリティルールは別途確認すること**（下の引き継ぎメモ）。

### チュートリアルの作り

読ませるのではなく、**操作させて覚えてもらう**形にしてある。

- 山札・サイコロの目・引き直しで引く札・相手の指し手まで、すべて固定。
  誰がいつ遊んでも同じ盤面・同じ順番になる
- 台本の1枚(step)は `text` と、必要なら `need`(やってほしい操作)を持つ。
  `need` があるあいだは**その操作以外を受け付けない**(`GameCore` の `y` で弾く)
- `focus` で、次に触る場所(手札の札・盤のマス・盤の駒・確定ボタン)を光らせ、
  その位置まで画面を自動で送る
- 説明だけの札を見ているあいだも、**この先の操作はそのまま受け付ける**。
  「次へ」を押さずに指しても案内が追いつく(`upcomingNeedStep`)。
  台本にない手は通さないので、盤面はずれない
- 説明は1〜2行。画面側の長い説明文は、チュートリアル中は隠す(`terse`)
- **相手の王がどこにいるかは案内に書かない。** 伏せられている情報なので、
  「c5 の駒を取ります」のようにマスの名前だけで指す
- 時間に追われずに済むよう、布陣の1分も対局の持ち時間も動かさない(`noLimit`)。
  制限時間があること自体は、台本の言葉で伝えている

4話とも、決まった手順で最後まで進み、あなたの勝ちで終わる。

| | プール | 手札 | 実際に起きること |
| --- | --- | --- | --- |
| 第1話 王を討つ | 2〜5 | 6枚 | 引き直し・布陣・王の選定・移動・**道連れ**・**王位継承**・決着 |
| 第2話 まとめて討つ | 2〜10 | 9枚 | 飛び越えて取る・桂馬・**王の6のまとめ取り(2体)** |
| 第3話 宮廷の札 | 2〜K | 13枚 | J/Q/K の動き・**Kの王が予備札を出す**・その配置 |
| 第4話 A の理 | A〜K | 13枚 | Aは動けない・**入れ替え**・**囲んでの撃破** |

台本を作るときは `tools/tutorial-lab.mjs` で手順が成立するか先に確かめ、
`tools/check-tutorial.mjs` で最後まで通ることを確認する。

`TEST_BUILD` が真のあいだだけ、URL に `?test=1` を付けると

## このソースの出どころ

v47 まではビルド済み HTML だけが残り、ソースが失われていた。
`reference/v47-build.html` から機械的に復元したのがこの `src/` で、
挙動が変わっていないことは照合ハーネスで担保している。

```
node tools/parity.mjs ./restored-logic.mjs
GAMES=1200 node tools/parity.mjs ./restored-logic.mjs   # 局数を増やす
```

元バンドルから抜き出した `reference/original-logic.mjs` を正として、
同じ状態・同じアクション・同じ乱数シードを与え、reducer / CPU / アクション補完の
出力が完全に一致するかをステップ単位で突き合わせる。

v48 で布陣と持ち時間を作り替えたので、**その2つは照合の対象から外してある**
(`tools/parity.mjs` の `DIVERGED_KEYS` と、`phase === "setup"` のスキップ)。
残り22アクション — 手の生成・撃破・王位継承・道連れ・予備札・Aの入れ替え — は
v47 と1ビットも変えていないことを、これまでどおり突き合わせている。

## BGM

場面が変わったら曲も変わる。曲は7本。

| 曲 | 鳴る場面 |
| --- | --- |
| `title` | タイトル・相手の選択・チュートリアル選択・ルール設定 |
| `waiting` | 相手を探しているあいだ・合言葉ルームで待っているあいだ |
| `setup` | 開始からサイコロ・引き直し・布陣・王の選定まで |
| `battle` | 対局 |
| `endgame` | 終盤の対局 |
| `win` / `lose` | 決着。ループしないので、鳴り終われば無音になる |

チュートリアル中は、考える邪魔をしないよう音量を一段下げる。

### 終盤かどうかの決め方

**公開されている情報だけで決めている。** 曲は両者に同じものが聞こえるので、
「王が危ない」で切り替えると、伏せてある王の正体を相手に教えてしまう。
だから見るのは次の2つだけで、どちらも画面に出ているものしか使っていない。

- どちらかの持ち時間が残り1分を切った
- 盤に残っている駒が、はじめの4割を下回った

一度終盤に入ったら戻らない。持ち時間は手番ごとに10秒足されるので、
その場で判定すると境目で曲が行ったり来たりする。

### 音のファイルだけは埋め込まない

カード画像は data URI で `index.html` に入れているが、曲は入れていない。
7本ぶんを埋めると HTML が1MB以上太り、**1曲も鳴らないうちに全部が落ちてくる**。
`assets/audio/*.m4a` を置いておくと、ビルドが `audio/` と `dist/audio/` へ写す。
実際に読むのは、その場面に来た曲だけになる。

### iOS で気をつけること

- **最初に画面を触るまで音は鳴らせない。** `armAudioUnlock()` が最初のタップを
  待ち受けて解錠する。それまでの再生指示は溜めておいて、解錠できた時点で流す
- **`<audio>` の `volume` は iOS では効かない。** 音量調整もクロスフェードも
  Web Audio の GainNode でやっているのはこのため
- WebView に包むときは、音を `file://` から読ませない。同じ生成元として
  扱われないと Web Audio に繋げられず、無音になる。ローカルサーバか
  `WKURLSchemeHandler` を通すこと

### 曲の差し替え

いま入っているのは `tools/make-placeholder-bgm.mjs` が作った**仮の音**で、
場面の切り替わりを耳で確かめるためだけのもの。本物が決まったら
`assets/audio/` の同じ名前の m4a を上書きすればよく、コードは触らなくていい。
音の大きさが他の曲と揃わないときは、`src/audio/tracks.js` の `gain` で合わせる。

## Firebase のセキュリティルール

2026-09-02 に実際の応答を確かめたところ、**読み取りは既に絞られていた**。

| 経路 | 結果 |
| --- | --- |
| `/` (ルート) | 401 拒否 |
| `/rooms` の一覧 | 401 拒否（部屋を数え上げられない） |
| `/rooms/{合言葉}` | 200（合言葉を知っていれば読める。これは必要） |
| `/lobby` | 200（マッチングに必要。中身は乱数のIDと時刻だけ） |

**書き込み側は未確認**。Firebase コンソールの「Realtime Database → ルール」で
いまの内容を見て、[firebase-rules.json](firebase-rules.json) の中身を貼って公開する。

このルールで防げること。

- ルートや `/rooms` への書き込みを塞ぐので、**まとめて消される事故が起きない**
- 書き込めるのは `/rooms/{合言葉}` と `/lobby/{合言葉}` の下だけ
- 合言葉の形（紛らわしい I と O を除いた4〜8文字）に合わないものは弾く
- ロビーに置けるのは `host` / `guest` / `createdAt` の3つだけ

**防げないこと。** 合言葉を知っている人は、その部屋を読み書きできる。
総当たりで当てることも理屈の上では可能（4文字なら約100万通り）。
そこまで塞ぐなら匿名ログイン(Anonymous Auth)を入れて、
`auth != null` と「その部屋の参加者か」で絞るのが本筋になる。いまは入っていない。

### プレイヤーのアカウント

はじめて開いたときに名前を決めてもらい、端末の localStorage に持つ
(`src/game/profile.js`)。名前・対局数・勝数・端末ごとの id が入っていて、
レベルは対局数と勝数から出す。名前を持たなかった頃の保存
(`tottery.profile.v1`)は1度だけ読み込んで引き継ぐ。

名前は部屋に載せて相手に渡す。ホストは `hostName`、参加者は `guestName`
を書き、相手のぶんを読んで `[先手の名前, 後手の名前]` にする。
それを `NamesProvider`(`src/ui/names.jsx`)で対局の画面全体に配る。

**対局の記録そのものは色(赤/青)のまま作る。** 名前で作ると、オンラインで
両者が同じアクション列を再生したときに食い違うし、名前を変えると過去の
記録まで変わってしまう。表示するときだけ名前に置き換えている
(`withNames` と `LogLine`)。1台で交互に指すときは誰の名前も無いので、
色名のまま出る。

レーティングやランキングを入れるときは、ここに rating を足すだけでは
足りない。いまの id は端末ごとの目印で、消して作り直せてしまう。
順位を competitive に保つなら、端末を替えても続くサーバー側の識別
(Sign in with Apple や Game Center など)が別に要る。

### 第5話・第6話 — 後手だから読める

どちらもサイコロが必ず後手になる目にしてある(`dice: [2, 6]`)。
引き直しは先手からなので、後手だと**相手の捨て札を見てから自分の
引き直しを決められる**。捨て札は公開情報で、引き直しの画面にそのまま出る。

- 第5話 … 後手のままでは相手に先に指される。ストレートがそろえば先手と
  後手が入れ替わるので、そこを取りに行く。捨て札に 7 が無い＝まだ残って
  いる、と読んでから狙う。**相手側では何も起こさない**(覚えることを
  ストレートひとつに絞る)
- 第6話 … 相手の捨て札に ♠ が1枚も無い。「♠ はまだ場に残っている」と
  読んでから、こちらはフラッシュを狙いに行く

引き直しの山(`reserveOrder`)は、**相手が先に引く枚数だけ空けてから**
狙いの札を置く(`reserveWith`)。空けないと相手が持っていってしまう。

読んでから決める回なので、説明だけの札は**盤の手前に出して操作を止める**
(`readFirst`)。ほかの話は下の帯のままで、指してもそのまま進める。
幕は薄くしてある。説明が指しているもの(捨て札など)が後ろで見えなく
なると、かえって分からなくなるため。

### 第5話 布陣の妙

布陣ボーナスを教える回。手札は 4・5・6・8 と、7 だけが抜けた並びで配る。
引き直しで 7♥ を引くとストレートがそろう。「引き直しは要らない札を
捨てる場ではなく、布陣を組み立てる場だ」と手で分かるようにしてある。
`reserveOrder` の先頭を 7♥ にして、必ずそれが来るようにしている。

相手はハートだけの布陣(フラッシュ)なので、こちらの駒が1枚めくられる。
1局で両方の効果を受けられる。

盤の上では 8♣ の進路を味方の 6♦ が塞いでいる。どかしてから進むと、
3マス先の相手を取れる。駒どうしの噛み合いをそのまま手にしてある。
`tools/check-tutorial.mjs` が、実際にストレートとフラッシュが起きて
先手が入れ替わることまで確かめる。

### 第6話 見えた1枚

フラッシュはこの回で初めて出す。第5話では相手側にも何もそろえていない。
1話で2つ覚えさせると、どちらの効果か分からなくなるため。

フラッシュで相手の 10♦ がめくれる。10 は桂馬なので跳べる先は2マスだけ。
伏せたままの駒と違い「どこまで届くか」が読めるので、それを確かめてから
Q♠ を踏み込ませる。分かった1枚をどう使うかが、この回のねらい。

めくれる駒は両者の布陣から決まるので、山札や布陣を変えると別の駒に
なる。`tools/check-tutorial.mjs` が「案内どおり 10♦ がめくれる」まで
見ているので、変えたときは検査が落ちて気づける。

### レーティングとランキング

`src/game/rating.js` が Elo。始めは1500で、勝てば上がり負ければ下がる。
強い相手に勝つほど大きく上がる。慣れるまで(10局)は動く幅を大きくして、
早く実力の位置に寄せる。

**数えるのはオンライン対戦だけ。** CPU戦とチュートリアルは相手の強さが
決まっていないので動かさない。相手の持ち点は、名前やアイコンと同じように
部屋へ載せて渡す(`hostRating` / `guestRating`)。

順位は `ranks/<id>` に置き、持ち点の高い順に読み出す
(`src/net/ranking.js`)。**この置き場所を使うには Firebase のルールに
ranks を足して公開する必要がある。**まだなら画面に「置き場所がまだ
開いていません」と出る。

**いまの順位は自己申告に近い。** id は端末ごとの目印で、消して入れ直せば
作り直せる。ルールの `.validate` は形と持ち点の範囲しか見ていないので、
他人の id に書き込むことも止められない。端末を替えても続く本人確認
(Sign in with Apple や Game Center)を入れて初めて、順位が意味を持つ。
画面にもそのことを書いてある。

### アイコンとスタンプの下準備

**アイコン**は `src/game/icons.js` に一覧がある。`free: true` は最初から
使えるもので、それ以外は `how` に手に入れ方を書く。持っているかは
`profile.icons` で見るので、対局の褒美として `grantIcon()` を呼べば増える。
一覧に1行足すだけで選べるようになる。

選んだアイコンは名前と同じように部屋へ載せて相手に渡す
(`hostIcon` / `guestIcon`)。対局中は時計の欄に出る。

**スタンプを置く場所**は、375×812 で実際に測って決めた。盤は横幅で
決まる正方形なので、5×5 でも 9×9 でも高さは変わらない。

```
0-59    上のバー
79-113  時計の欄     ← スタンプが「出る」場所
119-138 手番の帯
147-487 盤
503-525 失った駒
605-651 降参の行     ← スタンプを「送る」場所
        ↓ 161px 空いている
```

- **送るのは下の操作の行。** 降参するの隣。指が届く位置に 161px 空いている。
  盤の上に置くと駒に重なるので避ける。
- **出るのは時計の欄。** すでに席ごとに分かれていてアイコンと名前が並ぶので、
  誰が出したのかを言葉で書かなくても分かる。吹き出しは下へはみ出させる。
  そのために `.clock-cell` を position: relative にしてある。

**通信は対局のアクションとは別にする。** オンライン対戦は両者が同じ
アクション列を再生して盤面を作っている。スタンプは盤面を変えないので、
そこへ混ぜると再生が重くなるだけで良いことがない。`rooms/<code>/stamps` を
別に置いて、手番と同じように読み出す。

決まった絵柄だけを選ばせる(自由入力は入れない)、連打を止める、相手の
スタンプを切る、の3つは最初から要る。CPU戦とチュートリアルでは出さない。

### 布陣ボーナス

盤に並べた札の組み合わせで、対局が始まる前に一度だけ効果が出る
(`src/game/bonus.js`)。判定は盤に出した札すべてで行う。

- ストレート … 先手と後手が入れ替わる。両者そろえば元に戻る
- フラッシュ … 相手の王以外の駒が公開される(5×5は1枚、9×9は3枚)

Aは一番弱い札だが、Kの上に置く数え方(10-J-Q-K-A)も認める。

公開する駒は乱数で選ばない。オンラインでは両者が同じアクション列を
再生するので、ここで乱数を引くと画面がずれてしまう。代わりに両者の
布陣から決めている。相手の布陣は伏せられているから、どの駒が選ばれるかは
誰にも読めない。

チュートリアルは既定では効果を出さない(`scripted`)。先手が入れ替わったり
駒が公開されたりすると、台本の案内と噛み合わなくなるため。ただし
布陣ボーナスを教える第5話だけは `bonus: true` を立てて働かせている。

### 1ターンに2回動く王と、対局の記録

普通の駒の移動は対局の記録に残さない。残すのは撃破や王位継承といった
出来事だけで、全部の手を並べると読めなくなるため。

ただし王の10だけは例外にしてある。1ターンに2回動けるので、たとえば
1回目に取って2回目は動くだけ、という手になる。このとき2回目を残さないと、
記録の盤面と最後の盤面が食い違い、駒が動いた理由を読み取れない。
そこで取らずに動いただけの手も「赤が2回目に移動 (d2 → b1)」として
残し、撃破の行にも何回目かを添えている。記録に「王」とは書かない。

王のAの2回目は、もともと「入れ替えた」が記録に残るので足していない。

### 対局の記録から、その時の盤面へ

記録に残る出来事(撃破・道連れ・王位継承・入れ替え・予備札の投入・降参)が
起きるたび、`afterAction` がその時点の盤面を `state.replay` に控える。
盤の並びだけを写した軽いもので、1局あたり数十件にしかならない。

控えには盤の並びのほかに、その手の「出発点・着地点・倒れたマス」も入れて
ある。記録の行を押すと、出発点は破線の枠、着地点は金の「着」、倒れたマスは
赤い「×」で示す。

駒とマスはほぼ同じ大きさなので、着地点を枠で囲むと持ち主を示す色枠と
重なって色が濁る。そのため駒がいるマスは角のしるしで示し、枠の色は
持ち主(赤/青)だけに使う。

記録の行を押すと、まずその手の動きを再生する。駒は出発点から1マスずつ
進み、倒れたマスが光る。対局中と同じ演出をそのまま使っている。
動いている間は着地のしるしを伏せ、止まってから「ここへ動いて、ここを
取った」と示す。先に動きを見せたほうが分かりやすいため。

「対局を振り返る」で記録の行を押すと、その盤面に切り替わる。
過去の盤面には駒の来歴が無いので、駒をタップして動きを追えるのは
最終盤面のときだけ。

### 予備札を配置する画面

K の王が J か Q を失うと `kPlacement` が立ち、`ReservePlacer` が開く。
出す順は **撃破の札 → 予備札の配置**。何がどこで取られたか分かる前に
置き場所を選ばせても判断できないので、`captureReveal` が残っている間は開かない。

盤の駒は、**自分のものだけ表向き**に描く。自陣の空きと並びが見えないと
どこに置けばよいか決められない。相手の駒はこれまでどおり伏せたまま。

### 部屋の後始末

対局が終わってホストが画面を出るとき、`GameCore` の `leaveGame` が
その部屋を消す（`deleteRoom`）。消すのを**ホストだけ**にしているのは、
「もう一度遊ぶ」を選べるのがホストだけで、ゲストが先に抜けて部屋を消すと
ホストの再戦が壊れるため。

2026-09-02、実機のオンライン対戦を1局終えたあとに `rooms` が
空になっていることを確認済み。

決着せずに中断した部屋は残る。1局あたり約 11KB（200アクション）で、
無料枠の1GBには約97,000局入るので、当面は溜めておいても困らない。
気になったらコンソールの「データ」タブで `rooms` を消せばよい。

## 駒の動きと撃破の演出

駒は**1マスずつ進んで見える**。`lastMove` の出発点と到着点から
何マス進むかを数え、CSS の `steps(..., jump-none)` で途中のマスにも
一度ずつ立たせている(`.piece-stepping`)。桂馬だけは1回の跳躍にしてある。

駒が倒れたマスは `lastDefeat.cells` に順番に積まれる。
`--i` を渡して遅らせるので、**まとめ取りは1体ずつ順に光る**。
取った側は金色、取られた側は赤、A の包囲は紫で、広がる輪の色が変わる。

早すぎて見えないので、次の長さに調整してある。

| | |
| --- | --- |
| 1マス進むのにかかる時間 | 190ms（3マスなら 760ms） |
| 撃破の光 | 1.1秒（王が倒れたときは 1.7秒） |
| 撃破が始まるまで | 駒が動き出してから 260ms |
| 2体目以降の間隔 | 440ms |
| 相手が指すまでの間 | 1.2秒(チュートリアル) / 1.0秒(CPU戦) |

結果の札(「撃破!」)は、演出が終わるまで待たせている
(`holdFx` = 1500ms + 体数ぶん)。

### 王かどうかが分かる瞬間

取った駒は**伏せたまま出して、1枚ずつめくる**(420msごと)。
`captureReveal.defeated` は王を最後に並べ替えてあるので、
**最後の1枚をめくった瞬間に王だったと分かる**。そこで見出しが
「王を討った!」に変わり、冠がつく。すべてめくるまでボタンは押せない。

盤の上の演出(`lastDefeat.cells`)は並べ替えず、線に沿って手前から順に光る。
めくる順と光る順は別に持っている。

まとめ取りで王が混ざっていても、**取れる駒はすべて取ってから決着する**。
以前は王を取った時点で処理を打ち切っていたため、王だけ倒れて
ほかの駒が盤に残ることがあった。

## 6〜9 の動きを変えた (v48)

v47 では 6〜9 が**途中の駒を敵味方問わず飛び越えて**いた。
v48 では飛び越えない。**進路は塞がれる**。

- 進路に**味方**の駒があると、そこで止まって越えられない
- 進路に**相手**の駒があるとき、着地できる偶奇なら**取って止まる**
- 誰もいなければ、これまでどおり偶数マス／奇数マスに着地できる

王の 6〜9 の「まとめ取り」は残してある。相手を取りながら線上を進めるが、
**味方の駒には止められる**。

この変更により、**v47 との照合(`tools/parity.mjs`)はもう「変わっていないこと」の
保証にはならない**。復元が正しかったことの記録として残してあるが、
`npm run check` からは外した。単体で走らせたいときは `npm run parity`。

いまの安全網は次の3つ。

| | |
| --- | --- |
| `npm run check` | 布陣と持ち時間・チュートリアル4話・盤面の整合性 |
| `tools/check-board.mjs` | 対局を回しながら、盤と駒のずれを毎手たしかめる |
| 手での確認 | [動作確認.md](動作確認.md) |

## 引き継ぎメモ

- **王が6・7・8・9のとき、取れる手しか生成されない**（`board.js` の `jumpMoves` で
  `multiCapture` が真のとき、静かな移動を積んでいない）。元の実装のままにしてある。
  意図した仕様でなければ、ここを直せば王も普通に動けるようになる。
  **チュートリアル第2話は王を6に固定するので、この挙動が一番目につく話になっている。**
- **配信前に `src/game/profile.js` の `TEST_BUILD` を `false` にする。**
  いまはテストプレイ環境として、全プレイヤーをレベル10（全話開放）として扱っている。
- **持ち時間の時間切れは、時計を持っている側の端末が自分で申告する。**
  その端末が落ちたり、長くバックグラウンドに回ったままだと、相手はただ待つことになる。
  相手側からの申告を足すかどうかは、実機で様子を見てから決めるのがよい。
  なお、申告が遅れても取りこぼしはしない。持ち時間を超えて考えた手は reducer 側でも
  時間切れとして決着させている(`afterAction`)。
- **手番ごとの加算が10秒あるので、速く指し合うと持ち時間は増え続ける。**
  1手10秒未満で指す限り時計では終わらないので、決着は王を討つことだけになる。
  互いに動ける手が無くなった場合(たとえば王が6〜9で周りに敵がおらず、他の駒も
  塞がれている場合)、対局が終わらないままになる。千日手や手詰まりの扱いは未定。
- **布陣の1分と持ち時間は、端末のタブが裏に回ると進み方が変わる。**
  ブラウザは裏のタブのタイマーを大きく間引くため、裏で放置すると自動配置の発動が
  遅れる。表に戻った時点で判定し直すので取りこぼしはしないが、
  相手側からは「相手を待っている」時間が延びて見える。
- オンライン対戦は Realtime Database を**クライアントから直接**叩いている。
  ログインの仕組みが無いので、**合言葉(部屋コード)だけが鍵**になっている。
  推奨のルールを [firebase-rules.json](firebase-rules.json) に置いた。適用は下記。
