# Tottery

> **表示名は「Tottery」**（2026-09-05 に「トッタリー」から変えた）。
> 上のバー・ブラウザの見出し・管理画面はすべて Tottery。
> **タイトルの絵（`assets/ui/title-bg.webp`）にはまだ「トッタリー」が描き込まれている**
> ので、絵を作り直すまでは、そこだけ旧名のまま出る。
> 置き場のフォルダ名（`~/Desktop/トッタリー`）と商標メモはそのまま。
> 商標は [法務メモ.md](法務メモ.md) の頭に追記あり。


トランプ52枚を駒にした、2人用のカード×陣取りバトル。
1台の端末で交互に指すか、合言葉でルームを作ってオンラインで対戦する。CPU戦もある。

現在の版: **v49 (アカウント・布陣ボーナス・記録の再生・BGM)**

手で確かめる手順は [動作確認.md](動作確認.md) にまとめてある。
変更を入れたら、上から順に見ていけばよい。

## ビルド

```
npm install
npm run build     # index.html を生成
```

`index.html` は React もカード画像96枚も data URI で内包した単一ファイルで、
ゲーム本体はこれ1つで動く。BGMは `audio/`、スキン画像と動画は `skins/` も一緒に配信する。
`npm run build` で `dist/` に必要なファイルがすべて揃う。

## プレイヤーレベルと経験値

経験値は貯まる一方で、減らない。レベルはその総量から毎回導くので、保存するのは
経験値だけでよい。決まりは [src/game/level.js](src/game/level.js) の1か所。

```
レベル 1→2   100        レベル10まで +200 ずつ
      2→3   300
      …
      9→10 1700        ここまでの累計 8,100
     10→11 1800        ここから 1つ上がるごとに +20 ずつ重くなる
     99→100 3580       レベル100(上限)までの累計 250,200
```

経験値の入り口:

| どこで | 経験値 |
| --- | --- |
| 対戦を1局終える | 50 |
| 有償のガチャを1回引く | 150（いまは無料のテスト版なので、まだ配られない） |
| チュートリアルを1話終える | 話ごとに 100〜1500（次のレベルまでちょうど届く量）。**初回だけ** |

- 対戦だけなら **約5,000戦でレベル100**（250,200 ÷ 50 = 5,004戦）。
- チュートリアルは **1話終えるごとにレベルが1つ上がり、次の1話が開く**。
  各話の経験値は「次のレベルまでちょうど届く量」にしてある
  （第1話 100 → Lv2、第2話 300 → Lv3 … 第8話 1500 → Lv9）。
  **はじめての人がチュートリアルだけを進めても、段階的に開いてレベル10まで届く。**

  ただし12話に対してレベルは10段しかないので、2組だけ同時に開く。
  対になっている回を選んである — 第9・10話（どちらもAの回）と
  第11・12話（どちらも布陣ボーナスの回）。第10話を終えた時点でレベル10、
  全12話が開く。
- チュートリアルは対戦の数（`battles`）には数えない。ミッションの「対戦回数」用。

元の指示では 5→6 の行が抜けていたので、+200 ずつの等差として補ってある。
`EARLY_STEPS` を直せば、`npm run check` がチュートリアルの配分ごと確かめ直す。

## 通常ミッション

条件を満たすと、自分で「受け取る」を押して褒美をもらう。台帳は
[src/game/missions.js](src/game/missions.js) の1か所で、1行足せば増える。

| 条件 | 褒美 |
| --- | --- |
| 使用頻度（遊んだ日数） | 称号・スキン |
| プレイヤーレベル | ガチャチケット・アイコン |
| 対戦回数（チュートリアルは含めない） | ガチャチケット |

- 遊んだ日数は、アプリを開いたときに1日1回だけ数える（`touchDay`）。
  続けて遊んだ日数（`streak`）も持っているので、連続◯日の条件も足せる。
- **ガチャチケット**はスキンの持ち物（`tottery.skins.v1`）に貯まる。
  いまのガチャは無料・回数制限なしのテスト版なので、まだ減らない。
  有償・回数制にするときは `spendTickets` を引くだけでよい。
- 褒美の称号（常連・皆勤の士）とアイコン（王冠・星）は、条件では自動で
  開かない。受け取ってはじめて手に入る。
- 受け取れるものが複数あるときは、**まとめて受け取る**釦が出る。1件ずつ順に
  配って控えるので、途中で失敗してもそこまでは受け取れている。

## バトルパス

ビンゴのように、真ん中から外へ向かってマスを埋めていく。
決まりは [src/game/battlepass.js](src/game/battlepass.js) の1か所。

- 5×5の25マス。**真ん中の1マスは最初から空いている**（フリー）。
- 挑戦できるのは、**クリア済みのマスに縦横で隣り合うマスだけ**。斜めは開かない。
- 進むのは **相手の駒を取ったとき**。取った駒の中身でマスごとに数える
  （枚数・数字・まとめ取り・王を討つ）。1手ぶんは1回だけ数え、その手で
  新しく開いたマスは次の手から進む。
- クリアしたマスは **くるっと回ってめくれる**（表が条件、裏が絵柄の一片）。
  **もう一度押すと戻って、元の条件が読める。**「クリアしたマスを全部めくる」で
  まとめてめくれる（もう一度押すと全部が条件に戻る）。
- 全部めくると1枚の絵になり、その絵柄のスキンが手に入る（絵は褒美スキンの札を
  5×5に切って、マスごとに一片を出している）。
- チュートリアルでは進まない。

**マスの条件（`CELLS` の track と goal）は仮置き。** 中身が決まったらこの表だけ
差し替えれば、進み方も画面もそのまま動く。褒美のスキンも `REWARD_SKIN` の1行。

## ホーム

タイトルに置くのは**「ゲームスタート」だけ**。スキンはこの次のホームから入る。
遊び始める前に寄り道の口が見えていると、そちらへ流れてしまう。

「ゲームスタート」の次に出る、行き先を選ぶところ([src/ui/screens.jsx](src/ui/screens.jsx) の
`MenuScreen`)。片手で持った電話で見るところなので、**軽重をつけて**並べてある。

- 一番上は**自分の札**。名前・称号・レベルの帯・持っているチケット。押すと設定が開く
  (`useOpenSettings`。設定の札は `GameShell` が持っているので、下の画面へ手を渡している)
- **対戦する**だけを金の大きな釦にした。金はここにしか使わない
- 次に**チュートリアル**。始めたばかりの人が迷わないよう、対戦のすぐ下に置く
- **ミッション／バトルパス／ガチャ・装備**は四角い入り口。受け取れるものがあると
  右上に赤い印が出る。**左上は空けてある**（次に増やすものの席。`.home-slot`）
- **運営からのお知らせ**は読み物なので、四角ではなく**自分の札の上に細い帯**で置く。
  未読があるときだけ数を出す
- **ランキング**は毎日押すものではないので、下に文字だけで置く
- 絵柄と色は入り口ごとに変えてある。同じ絵柄が2つあると押し間違えるため
  (バトルパスは `Grid`、手紙は `Mail`)
- 触るところはどれも 44px 以上。iPhone SE(375×667)でも縦に溢れない

7つを同じ帯で並べていたときは、どれも同じ重さに見えて選べなかった。

## 王による移動距離の伸び

2〜5 を王にすると、移動できる距離が **「採用枚数 × 2マス」** 伸びる
（[src/game/board.js](src/game/board.js) の `rangeBonus`）。

| 王の数字 | 伸びるのは | 1枚採用 | 2枚 | 3枚 | 4枚 |
| --- | --- | --- | --- | --- | --- |
| **2・3** | **王自身** | 3マス | 5 | 7 | **9** |
| **4・5** | **王以外の同じ数字**（王自身は2マスのまま） | 4マス | 6 | **8** | 10 |

- 2・3 は小回りの利く王が、そのぶん遠くまで動ける
- 4・5 は王が動かず、**兄弟が前に出る**。4・5の王には道連れもあるので、
  同じ数字を前に置くほど強くなる
- 伸びるのは**距離の決まっている2〜5だけ**。6以降は「偶数マス」「何マスでも」と
  上限が無いので関わらない
- 枚数は**布陣したときに数えて固定**。倒れても減らない

早見表の「王にした時」の図で、4・5 は**王ではなく伸びたほうの駒**を描いている。
王自身は素のままなので、王として描くと通常の欄と同じ図になり、何が変わったのか
読めなくなるため。

## 駒が表になる3つの場面

伏せた駒の数字は、この3つでだけ相手に見える。

| 場面 | 表になる駒 |
| --- | --- |
| 布陣が**フラッシュ** | 相手が選ばれた枚数ぶん公開される（王は選ばれない） |
| **相手の王を討った** | 討った駒が、その場で名乗りを上げる（下） |
| **Kの王の予備札** | 予備札から出す駒は表向きで出る |

早見表の足元にも同じことを書いてある。

### Kの王の予備札は表向き

自分のJかQが倒されると予備札を1枚呼べる（`PLACE_RESERVE_CARD` in
[src/game/reducer.js](src/game/reducer.js)）。この駒は**表向きで盤に出る**。

どこからともなく1枚増えるので、伏せたままだと相手には「何が増えたのか」が
まるで読めない。Kの王の見返りは**駒数そのもの**なので、正体は明かして出す。
対局の記録にも数字が残り（「◯が予備札から 5♠ を投入(公開)」）、盤ではその駒が
くるりと表になる。

## 王を討った駒は名乗りを上げる

**相手の王を取った駒は、その場で表になって正体を明かす**（対局の決まり。
[src/game/reducer.js](src/game/reducer.js) の `removePiece`）。

- 王を取れば基本的に勝敗が決まるので、そこから先に隠しておく意味が薄い
- 2・3の王なら対局は続くが、そのぶんは**討った側が正体を明かす代償**として払う
- 記録にも「◯の3◆が名乗りを上げた!」と残り、盤ではその駒がくるりと表になる
  （`.piece-unveiled`）。「公開」の印も付く
- **包囲で討ったときは名乗らない。**名乗る駒が定まらないため

表になる場面は上の3つ。早見表の足元にもそう書いてある。

### スキンの映像を、いつ流すか

| 数字 | 映像が流れるとき |
| --- | --- |
| **2・3** | **王位継承**（王の2・3が討たれ、同じ数字が跡を継ぐ） |
| **4・5** | **道連れ**（王以外の4・5が取られ、取った相手も倒れる） |
| **6〜K** | **相手を取ったとき** |

**2〜5 は取っても流さない。**この4つの見せ場は効果のほうなので、取るたびに
出していると肝心の効果の映像が埋もれる（`ABILITY_RANKS` in
[src/skins/events.js](src/skins/events.js)）。

1手で複数起きたら、**取った側 → 道連れ → 王位継承**の順に続けて流れる
（`filmsFor`）。

### 誰の画面に流すか

- **取った側の映像**は、取った駒が**その手が終わった時点で表**なら相手にも流れる。
  伏せたままなら本人だけ。専用の映像から駒の正体が読めてしまうため
- **道連れ・王位継承の映像**は**どちらの画面にも**流れる。倒れた駒の数字はその場で
  公開されるし、跡を継げるのは決まりどおり同じ数字だけなので、新しく漏れる話は無い
- 王を討った駒は決まりで表になる（上）ので、王を取った手は自然に相手にも流れる。
  ただし 2〜5 は上の表のとおり、そもそも取ったときには流さない
- 道連れの場面では**取った側の映像も両方の画面に流れる**。巻き込まれた駒は倒れて
  失った駒の欄に並ぶので、その時点で正体が公になっているため

判定は「その手が終わった時点で正体が公になっているか」の一本だけ。**表になっている**
か、**倒れている**か。どちらも盤か札置き場を見れば分かることなので、映像で隠す意味がない。

## 錬成（エーテル）

ダブったスキンを崩して**エーテル**にし、**狙った1枚**を作る。決まりは
[src/skins/ether.js](src/skins/ether.js)、画面はスキンの「錬成」の欄。

### 値づけの根拠

抽選の中身は R 4枚で65%、SR 4枚で32%、**SSR 7枚**で3%。**1枚あたり**にすると
R 16.25% / SR 8% / SSR 0.4286%。崩してもらえる量は、この**出にくさに比例**させた。

| 格 | 1枚あたりの出る率 | 1枚を狙う平均 | 崩すと | 作るのに |
| --- | --- | --- | --- | --- |
| R | 16.25% | 6回 | **+10** | **40** |
| SR | 8% | 13回 | **+20** | **80** |
| SSR | 0.4286% | **233回** | **+375** | **1,500** |

R を 10 とすると SR は 16.25÷8 ≒ 2倍、SSR は 16.25÷0.4286 ≒ 37.9倍。きりのいい
ところで 10 / 20 / 375 にした。**作るのは崩すの4倍**。同じ格なら「ダブり4枚で
好きな1枚」。4倍にしたのは、1倍だと交換所になって引く意味が消え、10倍だと崩しても
届かず素材が死ぬため。

### SSR 1枚（1,500）に要るダブり

**R なら150枚 ・ SR なら75枚 ・ SSR なら4枚。**

これが妥当かは「何回引くぶんか」で確かめられる。1回引くごとに入るエーテルは
R から 0.65×10 = 6.5、SR から 0.32×20 = 6.4、SSR から 0.03×375 = 11.25。

| 集め方 | 1,500 貯まるまで |
| --- | --- |
| R だけを崩す | 約231回 |
| SR だけを崩す | 約234回 |
| （狙った SSR を運で当てる） | **233回** |
| 引いたものを全部崩す | **約62回** |

**単一の格を崩す道は運で当てるのとほぼ同じ手間、全部崩せば3.7倍速い。**
狙ってそう作ったのではなく、出にくさに比例させたことの帰結。
だから抽選の顔ぶれを変えたら、この表も一緒に動く（`tools/check-ether.mjs` が見張る）。
**画面に出す数字は `forgeSummary()` が抽選の中身から毎回引き直す**ので、手で書いた
数字が片方だけ古くなることはない（竜騎士を SSR に移したとき、実際に1か所取り残した）。

### 決まり

- **崩せるのは2枚目から。**最後の1枚は残るので、装備中の札が消えることはない
- **早期特典（LIMITED）は崩せないし作れない。**二度と手に入らないため。
  いまの早期特典は**白翼の天馬騎士だけ**。焔翼の竜騎士は SSR としてガチャに入っている
- **作るときは好きな1枚を選ぶ。**すでに持っている札も選べる（枚数が増える）
- エーテルは運営からのお知らせ・ミッションの褒美としても配れる（`{ type: "ether", amount }`）

## 画面をまたぐ決まりごと

- **「ホームに戻る」は `btn-home` を当てる**。どの画面でも同じ置き方(上に26px空け、
  幅200px、高さ48px、中央)。すぐ上の釦とくっついていると押し間違えるので、
  必ず間を空けて単体で立たせる
- **上の帯の左は、戻る先があるときだけ釦を出す**。飾りは置かない。
  押せそうに見えて何も起きないものは、電話では邪魔になる。
  桁(`.top-left`、幅72px)は空でも残す — 消すと真ん中の題がずれる

## ログインボーナス

1日1回、ホームに着いたときに札を出してガチャチケットを配る。決まりは
[src/game/login-bonus.js](src/game/login-bonus.js)、札は
[src/ui/loginbonus.jsx](src/ui/loginbonus.jsx)。

| 日 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| チケット | 1 | 1 | 1 | 2 | 1 | 1 | 3 |

- 7日でひと回り。合計10枚 = ちょうど10連が1回引ける。7日目を厚くしてあるのは
  「あと少しで大きいのが来る」を作るため
- **進み方は「受け取った回数」(`bonusTaken`)で数える。前の日から続いているかは
  見ない。** 続けて開けた人だけが得をする形にすると、1日空けただけで振り出しに
  戻り、そこで離れてしまう。休んでも続きから受け取れるほうがいい。
  続けた日数(`streak`)は褒美には効かせず、札に添えて出すだけ
- 最後に受け取った日(`bonusDay`)が今日と同じなら、もう出さない。
  同じ日に2回目を呼んでも増えない
- 出したら**受け取るまで閉じない**。うっかり外を押して流すと、その日はもう
  受け取れなくなるため
- 褒美の形はミッション・手紙と同じ(`{ type: "ticket", amount }`)なので、
  配り口は [src/game/gifts.js](src/game/gifts.js) を共通で使う

## 運営からのお知らせ

補填やプレゼントを渡すための一方向の連絡（コードの上では `letters`）。決まりは
[src/net/letters.js](src/net/letters.js)、配り口は [src/game/gifts.js](src/game/gifts.js)。

- 管理画面（`/admin`）の「運営からのお知らせ」から、**宛先（全員／特定の人）・件名・本文・
  添付**を選んで出す。添付はチケット／経験値／称号／アイコン／スキン。
  登録した人の詳細からも「手紙を出す」で宛先を選べる。
- プレイヤー側はホームの「運営からのお知らせ」の帯に**未読の数**が出る。開くと本文と添付が
  読め、「受け取る」で添付がその場で配られる。**未読ぶんをまとめて受け取る**釦もある。
- 受け取った印は端末（`profile.letters`）に控えるので、**二重取りにならない**。
  1通ずつ配ってから控えるので、途中で失敗してもそこまでは受け取れている。
- 期限（`until`）を過ぎた手紙は届かない。取り消せるのは、まだ受け取っていない人にだけ。
- サーバーには「誰が受け取ったか」を書かない。端末を替えれば取り直せてしまうが、
  いまは本人確認の仕組みが無いので割り切っている。

添付とミッションの報酬は同じ形（`{ type, id }` / `{ type, amount }`）にしてあるので、
配る処理は共通。

## 配信 (Cloudflare / Netlify)

GitHub の `main` へ push すると、配信先が組み立てて配信する。
設定はどちらの配信先でも同じで、次の3つだけ。

```
ビルド      : npm ci && node build.mjs
公開する場所: dist
Node の版   : .node-version(22。wrangler が 22 以上を要る)
```

`node build.mjs` は `index.html` と `dist/index.html` の両方を書き出す。
公開されるのは `dist/` だけなので、`src/` や `tools/` は配らない。
`dist/` は毎回作り直されるので git には入れていない。

### 配信先を Cloudflare にする

Netlify の無料枠は月の転送量に上限があり(100GB が目安)、初めての人1人に
約9MB(HTML 1.5MB + 曲 7.5MB)を配るので、人が増えると足りなくなる。
Cloudflare は無料枠でも転送量に上限がないので、こちらへ移す。

Cloudflare のダッシュボードで Workers & Pages → Create → Continue with GitHub
→ このリポジトリを選ぶ。設定は次の2つ。

```
Build command : npm ci && node build.mjs
Deploy command: npx wrangler deploy   (最初から入っている)
```

`npx wrangler deploy` は [wrangler.jsonc](wrangler.jsonc) を読んで `dist/` を
そのまま配る。サーバー側のコードは無い。以後は `main` への push で勝手に配信される。

Node の版は `.node-version` から読むので、環境変数は要らない
(wrangler が Node 22 以上を要るので 22 にしてある)。
ヘッダー(キャッシュの期限、nosniff など)は [_headers](_headers) に書いてあり、
ビルドが `dist/` に写す。Netlify も同じファイルを読むので、
[netlify.toml](netlify.toml) にはビルドの指定しか残していない。

### 転送量を抑える作り

- **曲は名前に中身のハッシュを埋めて配る**(`title.m4a` → `title.fc1fdfb2.m4a`)。
  `_headers` で `audio/` を1年キャッシュにしてあるので、同じ曲は二度と落ちてこない。
  曲を差し替えると名前が変わり、新しいほうだけ落ちてくる。
  元の名前との対応表はビルドが `__AUDIO_FILES__` として埋め込み、
  [src/audio/tracks.js](src/audio/tracks.js) の `audioUrl()` が引く。
  `TRACKS` や `SOUNDS` の `file` は元の名前のままでよい。
- **`index.html` は毎回確認させる**(`max-age=0, must-revalidate`)。
  変わっていなければ 304 で済み、更新したときはすぐ新しいものが届く。
- **App Store 版はアプリに同梱する**ので、配信先には一切アクセスしない。
  配信先が要るのはブラウザで試遊する人のためだけになる。

### 配信されたものが手元と同じか確かめる

Netlify は `</html>` のあとに計測用のスクリプトを1行足す(Cloudflare Pages は足さない)。
ファイル全体のハッシュを比べると必ず食い違うので、そこまでで切って比べる。

```
diff <(curl -s https://iridescent-pothos-77fe76.netlify.app/ | sed -n '1,/<\/html>/p') \
     <(sed -n '1,/<\/html>/p' dist/index.html)
```

オンライン対戦は Realtime Database をクライアントから直接叩いている。
配信先では通信の制限がないので、**そのまま対戦できる**。
ただし**データベース側のセキュリティルールは別途確認すること**（下の引き継ぎメモ）。

### チュートリアルの作り

読ませるのではなく、**操作させて覚えてもらう**形にしてある。

- 山札・サイコロの目・引き直しで引く札・相手の指し手まで、すべて固定。
  誰がいつ遊んでも同じ盤面・同じ順番になる
- 台本の1枚(step)は `text` と、必要なら `need`(やってほしい操作)を持つ。
  `need` があるあいだは**その操作以外を受け付けない**(`GameCore` の `y` で弾く)
- `focus` で、次に触る場所(手札の札・盤のマス・盤の駒・確定ボタン)を光らせ、
  その位置まで画面を自動で送る
- 説明だけの札を見ているあいだも、**この先の操作はそのまま受け付ける**。
  「次へ」を押さずに指しても案内が追いつく(`upcomingNeedStep`)。
  台本にない手は通さないので、盤面はずれない
- 説明は1〜2行。画面側の長い説明文は、チュートリアル中は隠す(`terse`)
- **相手の王がどこにいるかは案内に書かない。** 伏せられている情報なので、
  「c5 の駒を取ります」のようにマスの名前だけで指す
- 時間に追われずに済むよう、布陣の1分も対局の持ち時間も動かさない(`noLimit`)。
  制限時間があること自体は、台本の言葉で伝えている

4話とも、決まった手順で最後まで進み、あなたの勝ちで終わる。

| | プール | 手札 | 実際に起きること |
| --- | --- | --- | --- |
| 第1話 王を討つ | 2〜5 | 6枚 | 引き直し・布陣・王の選定・移動・**道連れ**・**王位継承**・決着 |

## BGM

場面が変わったら曲も変わる。曲は7本。

| 曲 | 鳴る場面 | 曲名 | 長さ |
| --- | --- | --- | --- |
| `title` | タイトル・相手の選択・チュートリアル選択・ルール設定 | 古の碑石 | 2:21 |
| `waiting` | 相手を探しているあいだ・合言葉ルームで待っているあいだ | ジェーン・グレイの肖像 | 2:23 |
| `setup` | 開始からサイコロ・引き直し・布陣・王の選定まで | 深い闇の奥で | 2:23 |
| `battle` | 対局 | 斜塔 | 3:56 |
| `endgame` | 終盤の対局 | 騎兵戦 | 1:42 |
| `win` | 決着(勝ち)。ループしない | ジングル01 | 0:04 |
| `lose` | 決着(負け)。ループしない | ジングル07 | 0:05 |

チュートリアル中は、考える邪魔をしないよう音量を一段下げる。
**BGM を切っているあいだは、音量を絞るのではなく曲を落としてこない。**

### クレジット

`title` から `endgame` の5本は[甘茶の音楽工房](https://amachamusic.chagasi.com/)、
`win` と `lose` は[魔王魂](https://maou.audio/)。どちらも商用利用可。

**魔王魂は「音楽：魔王魂」の表記が規約で必須。** 設定画面の「音」に
`MUSIC_CREDIT`（[src/audio/tracks.js](src/audio/tracks.js)）として出している。
ジングルを別の出どころに替えないかぎり、この行を消してはいけない。
甘茶の音楽工房は表記不要だが、揃えて並べてある。

### 終盤かどうかの決め方

**公開されている情報だけで決めている。** 曲は両者に同じものが聞こえるので、
「王が危ない」で切り替えると、伏せてある王の正体を相手に教えてしまう。
だから見るのは次の2つだけで、どちらも画面に出ているものしか使っていない。

- どちらかの持ち時間が残り1分を切った
- 盤に残っている駒が、はじめの4割を下回った

一度終盤に入ったら戻らない。持ち時間は手番ごとに10秒足されるので、
その場で判定すると境目で曲が行ったり来たりする。

### 音のファイルだけは埋め込まない

カード画像は data URI で `index.html` に入れているが、曲は入れていない。
7本ぶんを埋めると HTML が1MB以上太り、**1曲も鳴らないうちに全部が落ちてくる**。
`assets/audio/*.m4a` を置いておくと、ビルドが `audio/` と `dist/audio/` へ写す
(名前に中身のハッシュを埋めて写す。上の「転送量を抑える作り」)。
実際に読むのは、その場面に来た曲だけになる。

### iOS で気をつけること

- **最初に画面を触るまで音は鳴らせない。** `armAudioUnlock()` が最初のタップを
  待ち受けて解錠する。それまでの再生指示は溜めておいて、解錠できた時点で流す
- **`<audio>` の `volume` は iOS では効かない。** 音量調整もクロスフェードも
  Web Audio の GainNode でやっているのはこのため
- WebView に包むときは、音を `file://` から読ませない。同じ生成元として
  扱われないと Web Audio に繋げられず、無音になる。ローカルサーバか
  `WKURLSchemeHandler` を通すこと

### 音源の下ごしらえ

配布されている曲は**ループ用に作られていない**。そのまま繰り返すと、

- 頭に0.5秒、尻に3〜4秒の**無音**が入っている
- 終わりが30dB以上**フェードして終わる**ので、消えていきなり鳴り出す
- 出どころが違うと**大きさが揃わない**（今回は最大14dBの差があった）

`tools/prepare-bgm.mjs` が、無音を落とし、終わりのフェードを切り、
末尾と頭を等パワーのクロスフェードで繋いで、音量を -20dBFS に揃える。

```
node tools/prepare-bgm.mjs
```

読むのは `assets/audio/原曲/` に置いた配布ファイル。重いので git には
入れていないが、スクリプトの表に出どころの URL が並んでいるので、
落とし直せばいつでも同じものを作れる。

差し替えるときは、原曲を `原曲/` に置いてスクリプトの表を書き替えて走らせる。
場面ごとの音量の釣り合いは、音源ではなく [src/audio/tracks.js](src/audio/tracks.js)
の `gain` で決める。

## 効果音

3つだけ。[効果音ラボ](https://soundeffect-lab.info/)から取った。
商用無料・**クレジット表記不要**で、「ゲームやアプリの操作音として内蔵する」のは
再配布に当たらないと規約に明記されている。

| 音 | 鳴るとき | 元の音 |
| --- | --- | --- |
| `place` | 自分が駒を置いた・駒が動いた | カードを台の上に出す |
| `capture` | 駒が倒れた | 打撃1 |
| `tick` | 自分の残り時間が区切りを切った | 時計の針1 |

音源は `assets/audio/se-*.m4a`。`tools/prepare-se.mjs` が、配布ファイルから
使うところだけを切り出して作る。時計の針は14秒ぶん入っているので、
そこから針1つぶんだけ抜いている。3つ合わせて22KB しかないので、
BGM と違って**解錠のときに全部読んで、鳴らすときは待たせない**。

### 画面に音を鳴らす行を撒かない

効果音は、盤面の変わりかたから拾っている([src/audio/index.js](src/audio/index.js) の
`useGameSounds`)。置いた枚数・指した手数・倒れた駒の数を前の描画と比べて、
増えていたら鳴らす。こうすると、自分が指したときも CPU や相手が指したときも
同じように鳴り、画面のあちこちに音の呼び出しを書かずに済む。

**ここでも伏せた情報を漏らさない。** 置く音は自分が置いたときだけ鳴らす。
同時配置で相手の置いた瞬間まで聞こえると、相手がどこで手を止めているかが伝わる。
駒が倒れたことは盤を見れば分かるので、そちらは両方で鳴らす。

### 残り時間の知らせは秒読みにしない

`tick` は残り30秒と10秒を切った瞬間に**1回ずつ**鳴る
([src/audio/sounds.js](src/audio/sounds.js) の `TICK_AT_MS`)。
1秒ごとに鳴らすと「秒読みは無し」という決めごとと食い違うので、そうしていない。
布陣のあいだは置ける残り時間、対局中は自分の持ち時間を見る。
手番ごとに10秒足されて時間が戻れば、また同じ区切りで鳴る。

### 撃破のときは BGM を下げる

倒れた瞬間に `duckMusic()` で BGM を 0.35 倍まで落とし、0.7秒待ってから戻す。
効果音とぶつかって、どちらも潰れるのを避けるため。
効果音は duck を通していないので、一緒に下がることはない。

## Firebase のセキュリティルール

2026-09-02 に実際の応答を確かめたところ、**読み取りは既に絞られていた**。

| 経路 | 結果 |
| --- | --- |
| `/` (ルート) | 401 拒否 |
| `/rooms` の一覧 | 401 拒否（部屋を数え上げられない） |
| `/rooms/{合言葉}` | 200（合言葉を知っていれば読める。これは必要） |
| `/lobby` | 200（マッチングに必要。中身は乱数のIDと時刻だけ） |

**書き込み側は未確認**。Firebase コンソールの「Realtime Database → ルール」で
いまの内容を見て、[firebase-rules.json](firebase-rules.json) の中身を貼って公開する。

このルールで防げること。

- ルートや `/rooms` への書き込みを塞ぐので、**まとめて消される事故が起きない**
- 書き込めるのは `/rooms/{合言葉}` と `/lobby/{合言葉}` の下だけ
- 合言葉の形（紛らわしい I と O を除いた4〜8文字）に合わないものは弾く
- ロビーに置けるのは `host` / `guest` / `createdAt` の3つだけ

**防げないこと。** 合言葉を知っている人は、その部屋を読み書きできる。
総当たりで当てることも理屈の上では可能（4文字なら約100万通り）。
そこまで塞ぐなら匿名ログイン(Anonymous Auth)を入れて、
`auth != null` と「その部屋の参加者か」で絞るのが本筋になる。いまは入っていない。

### プレイヤーのアカウント

はじめて開いたときに名前を決めてもらい、端末の localStorage に持つ
(`src/game/profile.js`)。名前・対局数・勝数・端末ごとの id が入っていて、
レベルは対局数と勝数から出す。名前を持たなかった頃の保存
(`tottery.profile.v1`)は1度だけ読み込んで引き継ぐ。

名前は部屋に載せて相手に渡す。ホストは `hostName`、参加者は `guestName`
を書き、相手のぶんを読んで `[先手の名前, 後手の名前]` にする。
それを `NamesProvider`(`src/ui/names.jsx`)で対局の画面全体に配る。

**対局の記録そのものは色(赤/青)のまま作る。** 名前で作ると、オンラインで
両者が同じアクション列を再生したときに食い違うし、名前を変えると過去の
記録まで変わってしまう。表示するときだけ名前に置き換えている
(`withNames` と `LogLine`)。1台で交互に指すときは誰の名前も無いので、
色名のまま出る。

レーティングやランキングを入れるときは、ここに rating を足すだけでは
足りない。いまの id は端末ごとの目印で、消して作り直せてしまう。
順位を competitive に保つなら、端末を替えても続くサーバー側の識別
(Sign in with Apple や Game Center など)が別に要る。

### 1話でひとつだけ教える

初めての人には、1話で覚えることを増やしすぎない。第1話は
「並べて、動かして、王を討つ」だけにしてある。王位の継承も道連れも
起こらないよう、相手の王を 2♦ にして継承する駒を置いていない。

「王を取られたら負け」と言った同じ回で「取られたけど負けていない」を
見せると、初めての人には矛盾に映る。その2つは第2話でまとめて扱う。

**チュートリアルは台本が全て。** CPU には1手も指させない。1手でも
混ざると、そこから先は毎回ちがう盤面になり、決まった盤面を前提に
書いた案内と噛み合わなくなる。台本が足りているかは
`tools/check-tutorial.mjs` の「CPUは1手も指さない」が見張っている。

| 話 | Lv | 覚えること |
| --- | --- | --- |
| 1 はじめの一局 | 1 | 一局の流れ。並べる・動かす・取る・王を討つ |
| 2 王が継ぐ | 2 | 王位の継承 |
| 3 道連れ | 3 | 道連れ |
| 4 まとめて討つ | 4 | 進路を塞ぐ駒と、王のまとめ取り |
| 5 宮廷の札 | 5 | J・Q・K と、K の王の予備札 |
| 6 A の理 | 6 | 動かない A と、囲んでの撃破 |
| 7 布陣の妙 | 8 | ストレート。先手を取り返す |
| 8 見えた1枚 | 9 | フラッシュ。めくれた札の使い方 |

**王の力は、自分の軍で起きる形にしてある。** 継承は自分の王が取られて
自分の駒が継ぐ。道連れは自分の 4 が取られて相手を巻き込む。相手側で
起こすと、何が得で何が損なのかが伝わらない。

隣の話の効果が混ざらないよう、山札を組むときに相手の王の数字まで
決めてある。`tools/check-tutorial.mjs` が話ごとに「これは起きる／
これは起きない」を見張っている。

### 第7話・第8話 — 後手だから読める

どちらもサイコロが必ず後手になる目にしてある(`dice: [2, 6]`)。
引き直しは先手からなので、後手だと**相手の捨て札を見てから自分の
引き直しを決められる**。捨て札は公開情報で、引き直しの画面にそのまま出る。

- 第7話 … 後手のままでは相手に先に指される。ストレートがそろえば先手と
  後手が入れ替わるので、そこを取りに行く。捨て札に 7 が無い＝まだ残って
  いる、と読んでから狙う。**相手側では何も起こさない**(覚えることを
  ストレートひとつに絞る)
- 第8話 … 相手の捨て札に ♠ が1枚も無い。「♠ はまだ場に残っている」と
  読んでから、こちらはフラッシュを狙いに行く

引き直しの山(`reserveOrder`)は、**相手が先に引く枚数だけ空けてから**
狙いの札を置く(`reserveWith`)。空けないと相手が持っていってしまう。

読んでから決める回なので、説明だけの札は**盤の手前に出して操作を止める**
(`readFirst`)。ほかの話は下の帯のままで、指してもそのまま進める。
幕は薄くしてある。説明が指しているもの(捨て札など)が後ろで見えなく
なると、かえって分からなくなるため。

### 第7話 布陣の妙

布陣ボーナスを教える回。手札は 4・5・6・8 と、7 だけが抜けた並びで配る。
引き直しで 7♥ を引くとストレートがそろう。「引き直しは要らない札を
捨てる場ではなく、布陣を組み立てる場だ」と手で分かるようにしてある。
`reserveOrder` の先頭を 7♥ にして、必ずそれが来るようにしている。

相手はハートだけの布陣(フラッシュ)なので、こちらの駒が1枚めくられる。
1局で両方の効果を受けられる。

盤の上では 8♣ の進路を味方の 6♦ が塞いでいる。どかしてから進むと、
3マス先の相手を取れる。駒どうしの噛み合いをそのまま手にしてある。
`tools/check-tutorial.mjs` が、実際にストレートとフラッシュが起きて
先手が入れ替わることまで確かめる。

### 第8話 見えた1枚

フラッシュはこの回で初めて出す。第7話では相手側にも何もそろえていない。
1話で2つ覚えさせると、どちらの効果か分からなくなるため。

フラッシュで相手の 10♦ がめくれる。10 は桂馬なので跳べる先は2マスだけ。
伏せたままの駒と違い「どこまで届くか」が読めるので、それを確かめてから
Q♠ を踏み込ませる。分かった1枚をどう使うかが、この回のねらい。

めくれる駒は両者の布陣から決まるので、山札や布陣を変えると別の駒に
なる。`tools/check-tutorial.mjs` が「案内どおり 10♦ がめくれる」まで
見ているので、変えたときは検査が落ちて気づける。

### レーティングとランキング

`src/game/rating.js` が Elo。始めは1500で、勝てば上がり負ければ下がる。
強い相手に勝つほど大きく上がる。慣れるまで(10局)は動く幅を大きくして、
早く実力の位置に寄せる。

**数えるのはオンライン対戦だけ。** CPU戦とチュートリアルは相手の強さが
決まっていないので動かさない。相手の持ち点は、名前やアイコンと同じように
部屋へ載せて渡す(`hostRating` / `guestRating`)。

順位は `ranks/<id>` に置き、持ち点の高い順に読み出す
(`src/net/ranking.js`)。**この置き場所を使うには Firebase のルールに
ranks を足して公開する必要がある。**まだなら画面に「置き場所がまだ
開いていません」と出る。

**いまの順位は自己申告に近い。** id は端末ごとの目印で、消して入れ直せば
作り直せる。ルールの `.validate` は形と持ち点の範囲しか見ていないので、
他人の id に書き込むことも止められない。端末を替えても続く本人確認
(Sign in with Apple や Game Center)を入れて初めて、順位が意味を持つ。
画面にもそのことを書いてある。

### アイコンとスタンプの下準備

**アイコン**は `src/game/icons.js` に一覧がある。`free: true` は最初から
使えるもので、それ以外は `how` に手に入れ方を書く。持っているかは
`profile.icons` で見るので、対局の褒美として `grantIcon()` を呼べば増える。
一覧に1行足すだけで選べるようになる。

選んだアイコンは名前と同じように部屋へ載せて相手に渡す
(`hostIcon` / `guestIcon`)。対局中は時計の欄に出る。

**スタンプを置く場所**は、375×812 で実際に測って決めた。盤は横幅で
決まる正方形なので、5×5 でも 9×9 でも高さは変わらない。

```
0-59    上のバー
79-113  時計の欄     ← スタンプが「出る」場所
119-138 手番の帯
147-487 盤
503-525 失った駒
605-651 降参の行     ← スタンプを「送る」場所
        ↓ 161px 空いている
```

- **送るのは下の操作の行。** 降参するの隣。指が届く位置に 161px 空いている。
  盤の上に置くと駒に重なるので避ける。
- **出るのは時計の欄。** すでに席ごとに分かれていてアイコンと名前が並ぶので、
  誰が出したのかを言葉で書かなくても分かる。吹き出しは下へはみ出させる。
  そのために `.clock-cell` を position: relative にしてある。

**通信は対局のアクションとは別にする。** オンライン対戦は両者が同じ
アクション列を再生して盤面を作っている。スタンプは盤面を変えないので、
そこへ混ぜると再生が重くなるだけで良いことがない。`rooms/<code>/stamps` を
別に置いて、手番と同じように読み出す。

決まった絵柄だけを選ばせる(自由入力は入れない)、連打を止める、相手の
スタンプを切る、の3つは最初から要る。CPU戦とチュートリアルでは出さない。

### 布陣ボーナス

盤に並べた札の組み合わせで、対局が始まる前に一度だけ効果が出る
(`src/game/bonus.js`)。判定は盤に出した札すべてで行う。

- ストレート … 先手と後手が入れ替わる。両者そろえば元に戻る
- フラッシュ … 相手の王以外の駒が公開される(5×5は1枚、9×9は3枚)

Aは一番弱い札だが、Kの上に置く数え方(10-J-Q-K-A)も認める。

公開する駒は乱数で選ばない。オンラインでは両者が同じアクション列を
再生するので、ここで乱数を引くと画面がずれてしまう。代わりに両者の
布陣から決めている。相手の布陣は伏せられているから、どの駒が選ばれるかは
誰にも読めない。

チュートリアルは既定では効果を出さない(`scripted`)。先手が入れ替わったり
駒が公開されたりすると、台本の案内と噛み合わなくなるため。ただし
布陣ボーナスを教える第7話だけは `bonus: true` を立てて働かせている。

### 1ターンに2回動く王と、対局の記録

普通の駒の移動は対局の記録に残さない。残すのは撃破や王位継承といった
出来事だけで、全部の手を並べると読めなくなるため。

ただし王の10だけは例外にしてある。1ターンに2回動けるので、たとえば
1回目に取って2回目は動くだけ、という手になる。このとき2回目を残さないと、
記録の盤面と最後の盤面が食い違い、駒が動いた理由を読み取れない。
そこで取らずに動いただけの手も「赤が2回目に移動 (d2 → b1)」として
残し、撃破の行にも何回目かを添えている。記録に「王」とは書かない。

王のAの2回目は、もともと「入れ替えた」が記録に残るので足していない。

### 対局の記録から、その時の盤面へ

記録に残る出来事(撃破・道連れ・王位継承・入れ替え・予備札の投入・降参)が
起きるたび、`afterAction` がその時点の盤面を `state.replay` に控える。
盤の並びだけを写した軽いもので、1局あたり数十件にしかならない。

控えには盤の並びのほかに、その手の「出発点・着地点・倒れたマス」も入れて
ある。記録の行を押すと、出発点は破線の枠、着地点は金の「着」、倒れたマスは
赤い「×」で示す。

駒とマスはほぼ同じ大きさなので、着地点を枠で囲むと持ち主を示す色枠と
重なって色が濁る。そのため駒がいるマスは角のしるしで示し、枠の色は
持ち主(赤/青)だけに使う。

記録の行を押すと、まずその手の動きを再生する。駒は出発点から1マスずつ
進み、倒れたマスが光る。対局中と同じ演出をそのまま使っている。
動いている間は着地のしるしを伏せ、止まってから「ここへ動いて、ここを
取った」と示す。先に動きを見せたほうが分かりやすいため。

「対局を振り返る」で記録の行を押すと、その盤面に切り替わる。
過去の盤面には駒の来歴が無いので、駒をタップして動きを追えるのは
最終盤面のときだけ。

### 予備札を配置する画面

K の王が J か Q を失うと `kPlacement` が立ち、`ReservePlacer` が開く。
出す順は **撃破の札 → 予備札の配置**。何がどこで取られたか分かる前に
置き場所を選ばせても判断できないので、`captureReveal` が残っている間は開かない。

盤の駒は、**自分のものだけ表向き**に描く。自陣の空きと並びが見えないと
どこに置けばよいか決められない。相手の駒はこれまでどおり伏せたまま。

### 部屋の後始末

対局が終わってホストが画面を出るとき、`GameCore` の `leaveGame` が
その部屋を消す（`deleteRoom`）。消すのを**ホストだけ**にしているのは、
「もう一度遊ぶ」を選べるのがホストだけで、ゲストが先に抜けて部屋を消すと
ホストの再戦が壊れるため。

2026-09-02、実機のオンライン対戦を1局終えたあとに `rooms` が
空になっていることを確認済み。

決着せずに中断した部屋は残る。1局あたり約 11KB（200アクション）で、
無料枠の1GBには約97,000局入るので、当面は溜めておいても困らない。
気になったらコンソールの「データ」タブで `rooms` を消せばよい。

## 駒の動きと撃破の演出

駒は**1マスずつ進んで見える**。`lastMove` の出発点と到着点から
何マス進むかを数え、CSS の `steps(..., jump-none)` で途中のマスにも
一度ずつ立たせている(`.piece-stepping`)。桂馬だけは1回の跳躍にしてある。

駒が倒れたマスは `lastDefeat.cells` に順番に積まれる。
`--i` を渡して遅らせるので、**まとめ取りは1体ずつ順に光る**。
取った側は金色、取られた側は赤、A の包囲は紫で、広がる輪の色が変わる。

早すぎて見えないので、次の長さに調整してある。

| | |
| --- | --- |
| 1マス進むのにかかる時間 | 190ms（3マスなら 760ms） |
| 撃破の光 | 1.1秒（王が倒れたときは 1.7秒） |
| 撃破が始まるまで | 駒が動き出してから 260ms |
| 2体目以降の間隔 | 440ms |
| 相手が指すまでの間 | 1.2秒(チュートリアル) / 1.0秒(CPU戦) |

結果の札(「撃破!」)は、演出が終わるまで待たせている
(`holdFx` = 1500ms + 体数ぶん)。

### 王かどうかが分かる瞬間

取った駒は**伏せたまま出して、1枚ずつめくる**(420msごと)。
`captureReveal.defeated` は王を最後に並べ替えてあるので、
**最後の1枚をめくった瞬間に王だったと分かる**。そこで見出しが
「王を討った!」に変わり、冠がつく。すべてめくるまでボタンは押せない。

盤の上の演出(`lastDefeat.cells`)は並べ替えず、線に沿って手前から順に光る。
めくる順と光る順は別に持っている。

まとめ取りで王が混ざっていても、**取れる駒はすべて取ってから決着する**。
以前は王を取った時点で処理を打ち切っていたため、王だけ倒れて
ほかの駒が盤に残ることがあった。

## 6〜9 の動きを変えた (v48)

v47 では 6〜9 が**途中の駒を敵味方問わず飛び越えて**いた。
v48 では飛び越えない。**進路は塞がれる**。

- 進路に**味方**の駒があると、そこで止まって越えられない
- 進路に**相手**の駒があるとき、着地できる偶奇なら**取って止まる**
- 誰もいなければ、これまでどおり偶数マス／奇数マスに着地できる

王の 6〜9 の「まとめ取り」は残してある。相手を取りながら線上を進めるが、
**味方の駒には止められる**。

この変更により、**v47 との照合(`tools/parity.mjs`)はもう「変わっていないこと」の
保証にはならない**。復元が正しかったことの記録として残してあるが、
`npm run check` からは外した。単体で走らせたいときは `npm run parity`。

いまの安全網は次の3つ。

| | |
| --- | --- |
| `npm run check` | 布陣と持ち時間・チュートリアル4話・盤面の整合性 |
| `tools/check-board.mjs` | 対局を回しながら、盤と駒のずれを毎手たしかめる |
| 手での確認 | [動作確認.md](動作確認.md) |

## 引き継ぎメモ

- **王が6・7・8・9のとき、取れる手しか生成されない**（`board.js` の `jumpMoves` で
  `multiCapture` が真のとき、静かな移動を積んでいない）。元の実装のままにしてある。
  意図した仕様でなければ、ここを直せば王も普通に動けるようになる。
  **チュートリアル第2話は王を6に固定するので、この挙動が一番目につく話になっている。**
- **配信前に `src/game/profile.js` の `TEST_BUILD` を `false` にする。**
  いまはテストプレイ環境として、全プレイヤーをレベル10（全話開放）として扱っている。
- **持ち時間の時間切れは、時計を持っている側の端末が自分で申告する。**
  その端末が落ちたり、長くバックグラウンドに回ったままだと、相手はただ待つことになる。
  相手側からの申告を足すかどうかは、実機で様子を見てから決めるのがよい。
  なお、申告が遅れても取りこぼしはしない。持ち時間を超えて考えた手は reducer 側でも
  時間切れとして決着させている(`afterAction`)。
- **手番ごとの加算が10秒あるので、速く指し合うと持ち時間は増え続ける。**
  1手10秒未満で指す限り時計では終わらないので、決着は王を討つことだけになる。
  互いに動ける手が無くなった場合(たとえば王が6〜9で周りに敵がおらず、他の駒も
  塞がれている場合)、対局が終わらないままになる。千日手や手詰まりの扱いは未定。
- **布陣の1分と持ち時間は、端末のタブが裏に回ると進み方が変わる。**
  ブラウザは裏のタブのタイマーを大きく間引くため、裏で放置すると自動配置の発動が
  遅れる。表に戻った時点で判定し直すので取りこぼしはしないが、
  相手側からは「相手を待っている」時間が延びて見える。
- オンライン対戦は Realtime Database を**クライアントから直接**叩いている。
  ログインの仕組みが無いので、**合言葉(部屋コード)だけが鍵**になっている。
  推奨のルールを [firebase-rules.json](firebase-rules.json) に置いた。適用は下記。

## スキンガチャ（テスト版）

タイトルまたは対戦メニューの「スキンガチャ・装備」から開く。

- 1回・10回とも無料、回数・チケット制限なし。
- R 65%、SR 32%、SSR 3%。各回独立、10回の確定枠なし。
- 通常14種。Rは各16.25%、SRは各8%、SSRは各0.5%。
- 10のドラゴンナイトとペガサスナイトは、別途「早期特典を受け取る」で1回だけ配布。
- 獲得後に装備する。同じランクの全スートに適用され、能力・移動・勝敗のルールは変わらない。
- 装備は手札、布陣、盤面、公開された相手札、撃破結果、対局の記録に反映。
- オンラインは対局開始時の装備IDを部屋へ渡す。裏札は元の裏面を保つ。CPUのカードは通常デザイン。
- 所持数・装備・未確認の結果・演出設定は `tottery.skins.v1` に端末保存。旧プレビューの保存データが同じオリジンにあれば引き継ぐ。端末間同期はしない。
- 抽選結果を保存してから5秒の召喚演出へ進む。スキップや再読み込みで獲得結果を失わない。重複は所持数に加算。

バトル動画は16種すべてに同梱(各5秒・縦720×1280・効果音入り。`assets/skins/videos/<id>.mp4`)。
装備した駒が実際に相手を取ったときに再生し、通常移動や裏向きの相手の攻撃では出さない。
演出中はローカル操作・CPU・持ち時間を待機させ、終了・スキップ・読み込み失敗で復帰する。
通常5秒／短縮2秒／なしを選択でき、OSの動きを減らす設定にも従う。
チュートリアルは従来のカード・演出を使う。

設定は `src/skins/catalog.js`、抽選・保存は `src/skins/collection.js` と `store.js`。
素材原本は `assets/skins/`。ガチャUIは `src/ui/skins.jsx`。
`npm run check` に抽選分布、永続化、重複、装備制約、隠し情報、実際のreducerとの接続検査を含む。
