# 英語版: 画面の文の移し方(作業する人向け)

仕組みは [仕組みの形.md](仕組みの形.md)、言葉は [訳語の表.md](訳語の表.md)。

## 約束

1. **日本語の表示は一字も変えない。** 句読点・空白・改行・全角半角まで。日本語の端末ではキーがそのまま出る
2. 英語にするのは、受け持ちのファイルの、画面に出る日本語の文すべて(釦・見出し・説明・aria-label・
   title・alt・エラー文・ルールの説明・カードの名前と説明・称号の名前・チュートリアルの台本・詰めの問題)
3. 注釈(`//`・`/* */`)は日本語のまま。`console.*` の文は訳さない
4. 辞書は**自分の辞書ファイルだけ**に足す(`src/i18n/en/<受け持ち>.js`)。ほかの人の辞書・
   `src/i18n/en/index.js`・`src/i18n/index.js`・`tools/i18n-pending.txt`・`tools/i18n-baseline.json` は触らない
5. 受け持ち以外のファイルは触らない。どうしても要るときは作業の報告に書く

## 書き方

```jsx
import { L, Lk, Lx, fmtNumber, fmtDate, LOCALE } from "../i18n/index.js";

<button>{L("挑戦する")}</button>
<p aria-label={L("閉じる")}>…</p>
`フレンドは${n}人までです。`   →  L("フレンドは{n}人までです。", { n })
```

- **L の1つ目は文字列そのもの**(テンプレートや変数は不可)。差し込みは `{名前}`(英字・数字・_)
- 文の途中で JSX の式が挟まる文(「続けるには{store}で更新」など)は、英語の語順が違うので
  **1つの L にまとめる**。日本語の出方(空白も)が前と同じになるように組む。
  JSX の改行と字下げは消える・`{" "}` は空白1つ、を思い出して、出来上がりの日本語を前と同じにする
- 太字や色を文の途中に入れている(`<b>`)場合は、文を「前・太字・後」に分けて訳してよい
  (英語で語順が崩れないか確かめる)。分けると不自然なら、`{b}` を差し込みにして
  `L("…{b}…", { b: <b>…</b> })` の形は使えない(L は文字列を返す)ので、
  `const [pre, post] = L("…{b}…").split("{b}")` のように切って組む
- **保存する・サーバーや相手に送る・ほかの文と比べる(`=== "…"`)日本語は、値を変えない。**
  定義のところは `Lk("…")`(値は日本語のまま・英訳の有無だけ検査される)、出すところで `Lx(値)`。
  使われ方は grep で必ず確かめる。迷ったら Lk + Lx
- サーバー(`src/server/`)から返す日本語のエラー文は `Lk("…")`(`{n}` もそのまま `Lk("…{n}…", { n })`)。
  アプリの側で返事のエラーを画面に渡すところで `Lx(…)` を通す
- データの表(カードの名前・説明、称号の名前など)で、値が保存も比較もされないものは、
  定義のところで `L("…")` にしてよい(言語は起動のときに決まり、途中で変わらない)
- `toLocaleString("ja-JP")` → `fmtNumber(n)`、`Intl.DateTimeFormat("ja-JP", opts)` → `fmtDate(d, opts)`
  または `new Intl.DateTimeFormat(LOCALE, opts)`。日本時間で決めている時刻は `timeZone: "Asia/Tokyo"` のまま
- 「{n}枚」のように英語で単数・複数が変わるものは、英語を "x{n}" などにして崩れないようにする
- 画面に出ない日本語(内部の目印・比べるためだけの値・正規表現)は、その行か前の行に
  `// i18n-ignore` と書く(JSX の中なら `{/* i18n-ignore */}`)。安易に使わない

## 確かめ方

```bash
I18N_DONE="src/ui/a.jsx src/ui/b.jsx" node tools/check-i18n.mjs
```

受け持ちのファイルを I18N_DONE に並べると、取り残し・英訳の抜け・日本語の変化を見る。
**sandbox の外で走らせる**(中だと babel が MODULE_NOT_FOUND)。ほかの人も同時に移しているので、
受け持ち以外のファイルの NG は無視してよい。

あわせて、受け持ちのファイルに関わる `tools/check-*.mjs` を走らせる(ファイル名で `grep -l` して探す)。
`npm run build`・`npm run check` 全体は走らせない(ほかの人の途中の作業とぶつかる)。
