# 英語版: 仕組みの形(案)

## 一言で

**日本語の文そのものを辞書のキーにする。** 画面のコードは日本語のまま読めて、日本語の端末では
キーをそのまま出すので、日本語の表示は一字も変わらない。英語の端末では英語の辞書を引く。

```jsx
// いま
<button>挑戦する</button>
<p>{`フレンドは${FRIEND_MAX}人までです。`}</p>

// これから
import { t } from "../i18n/index.js";
<button>{t("挑戦する")}</button>
<p>{t("フレンドは{n}人までです。", { n: FRIEND_MAX })}</p>
```

```js
// src/i18n/en.js(英語の辞書。日本語 → 英語)
export const EN = {
  "挑戦する": "Try it",
  "フレンドは{n}人までです。": "You can have up to {n} friends.",
  ...
};
```

## 置くもの

| ファイル | 中身 |
|---|---|
| `src/i18n/index.js` | `LANG`(`"ja"` か `"en"`)・`t(日本語, 差し込み)`・日付と数の書式(`fmtDate`・`fmtNumber`) |
| `src/i18n/en.js` | 英語の辞書。画面のまとまり(E1〜E9)ごとに区切って並べる |
| `tools/check-i18n.mjs` | 検査(下)。`package.json` の check に入れる |

## 言語の決め方

- 端末の言語の1番目(`navigator.languages[0]`)が日本語(`ja`)なら日本語、それ以外は全部英語
- 起動のときに一度だけ決める。途中で変えたら次の起動から
- 確かめ用に、ブラウザでは `?lang=en` / `?lang=ja` で切り替えられるようにする(プレビューで両方を見るため)

## サーバーのエラー文

Worker は今のまま日本語で返す。アプリの側で、返ってきた日本語を同じ辞書で英語に引く
(数の入る文は形で当てる)。Worker を直さないので、配備の順番を気にしなくてよい。

## 日本語が変わらないことの守り方

1. `t()` は日本語の端末ではキーをそのまま返すだけ。差し込み(`{n}`)は今の `${}` と同じ位置に入る
2. 移す前と後で、画面に出る日本語の一覧(Babel で拾ったもの)を突き合わせる。1字でも違えば検査が落ちる
3. 移すのは画面のまとまりごと。1つ移すたびに check を通し、プレビューで日本語と英語の両方を見る

## 検査(tools/check-i18n.mjs)

- **抜け**: `t()` のキーのうち、英語の辞書に無いものがあれば落ちる
- **取り残し**: 英語にすると決めたファイルに、`t()` を通らない日本語の文が残っていれば落ちる
  (日本語のままにすると決めたもの(C1〜C3、Q で日本語のままに決めたもの)は除く)
- **差し込みのずれ**: 日本語と英語で `{n}` などの数・名前が合わなければ落ちる
- **日本語の端末**: `LANG=ja` で `t()` がキーと同じ文を返すこと
- **英語の端末**: `LANG=en` で `t()` が日本語の字を1つも含まない文を返すこと
- **使われていない英訳**: 画面から消えた文の英訳が辞書に残っていれば知らせる

## iOS

- `Info.plist`: `CFBundleDevelopmentRegion` は `ja` のまま。`CFBundleLocalizations` に `ja` と `en` を足す
- `project.pbxproj`: `knownRegions` に `en` を足す
- `en.lproj/InfoPlist.strings`: 許可の文3つ(近くの端末・Bluetooth・追跡)の英語と、ホーム画面の下の名前

## App Store のページ

App Store Connect の API で、英語(en-US)の説明文・キーワード・サブタイトル・新機能の文を足す。
載せる前に英語の文をお見せして確認をとる。
