# ホームの着せ替え

設定の「ホームの着せ替え」から、フェーズごとに物語連動・フェーズ専用・領域やキャラのホーム装飾を選ぶ。
承認済みの背景・王のイラスト・各エリア固有のフレームを使い、既存の残高、
プレイヤー情報、通知、各メニューの動作をそのまま表示する。

## 物語の現在地

着せ替え画面の上部で「ストーリーに連動」と「背景を選ぶ」を切り替える。
「ストーリーに連動」では、現在のフェーズの次の未クリア話を背景にする。
現在の話数・タイトル・背景を確認し、「ストーリー連動を使う」で適用する。
「ストーリーの背景」には、選択中のフェーズの第1話〜第7話を常時表示する。
話数を選んで「この話の背景を使う」を押すと、その背景へ固定できる。未クリア話も選択できる。
背景の選択ではクリア記録や報酬を変更しない。自動に戻す場合は「ストーリーに連動」を選ぶ。
「背景を選ぶ」では従来の背景一覧を表示し、選んだ背景を固定する。
画面を閉じるまでは、連動表示を試しても直前に選んだ固定背景へ戻せる。
3フェーズ×7話の21枚を原稿の舞台に合わせて制作し、村の戦火や再建、港の占領、
砦の開閉など同じ土地の変化も描き分ける。話のタイトルと現在地も画面へ表示する。
話を順不同にクリアしても、ストーリー一覧と同じ最初の未クリア話を表示する。
全7話クリア後は最終話の背景を保持し、昇格後は新しいフェーズの最初の未クリア話へ移る。
再戦・漫画の読了・プレビューでは進行を変更しない。

着せ替えは`collection.phaseHomes`へフェーズ別に保存する。未設定の既存データは
従来の装飾・キャラ選択を引き継ぐ。手動の装飾を選んだフェーズではその選択を維持し、
「ストーリーに連動」に戻すと現在の進行に追従する。

本番用の背景は`assets/skins/home-story-v1/`、フェーズ専用の3枚は
`assets/skins/home-phases-v2/`。built-in image_genで制作し、元画像を残してWebPへ圧縮した。
追加制作も既存カード・物語の背景と同じ高精細な描画、素材感、光と空気感を最低基準とする。
簡単な図形・グラデーション・仮のベクター背景で代用しない。
各話の制作プロンプトは`reports/home-story-20261023/art-plan.json`、
生成元と保存先の対応は同フォルダの`sources.json`に記録する。

`node tools/check-home-story.mjs`で全21話・原稿のタイトル・進行・手動設定を確認する。
`node tools/build-home-story-preview.mjs [出力先]`は実際のGameShell/MenuScreenから
各フェーズ・各話を切り替えられる画面プレビューを再生成する。

## ホームBGMの選択

設定の「音と演出」→「ホームBGM」で、背景に合わせるおまかせと、曲の固定を選ぶ。
選択は端末共通の`tottery.home-music.v1`へ保存し、フェーズや背景の変更ではリセットしない。
未設定・不正な保存は「背景に合わせる（おまかせ）」として扱う。音量・消音とは別に保存する。

おまかせは、ホームに実際に表示する`homeThemeForProfile(collection, profile)`を基準にする。
ストーリー連動中と、各話の背景を固定した場合は、その背景のフェーズに関連する採用曲を使う。
現在の進行と違うフェーズの話を固定している場合も、表示中の背景に合わせる。
フェーズ専用ホーム・領域・キャラなど、ストーリー以外の背景では標準のホームBGMを使う。

| 選べる曲 | 用途・おまかせの対応 | 繰り返す本体 |
| --- | --- | --- |
| 標準のホームBGM | 以前採用した②のループ版。ストーリー以外の背景の標準 | 約92秒 |
| 風と土の道 | ギター＋クラリネット。フェーズ1のストーリー背景 | 約108秒 |
| 息をつく場所 | バスクラリネット＋ハルモニウム。フェーズ2のストーリー背景 | 約89秒 |
| 手を重ねた朝 | アコーディオン＋ギター。フェーズ3のストーリー背景 | 約104秒 |

4曲とも進行に関係なく自由に選べる。手動選曲はストーリー背景より優先する。
選択を変えるとホームと同じ曲を共有する画面へ反映し、対局など専用曲のある場面では
その場面の曲を維持する。背景のプレビューだけでは曲を変えず、保存された背景に従う。
同じ曲の画面の往復や、名前・所持品だけの更新でも曲を先頭から流し直さない。

導入は初回だけ流し、その後は拍・旋律・和音の近いフレーズへ戻る。
反復点の前後には同じ録音の余韻を配置し、AACのファイル端や無音をループに含めない。
バックグラウンドでは一時停止し、復帰時には同じ曲の停止位置から続ける。
音量と消音は既存のアプリ内音声設定に従う。

標準曲は、チャットの試聴で指定された`assets/audio/masters/home-soft-loop-20261023.m4a`を
`homeDefault.m4a`として無変換で同梱する。音程・速度・音色の加工を加えず、
トラック側の追加の音量補正を外し、定常時は本人のBGM音量だけを反映する。
BGM設定100%では原本と等倍、既定の60%では0.6倍になる。
切り替え時のフェード・演出時の一時的な音量調整とバックグラウンド停止・続き再生は維持する。
iOSアプリは全19曲のBGMと、操作・報酬・撃破・領域・召喚・動画音声を
`NativeHomeMusicPlugin`経由の`AVAudioEngine`で再生する。標準曲で実機確認済みの
経路を広げ、Web Audioのデコード・再生から独立させる。BGMの音程・速度の加工はしない。
初回区間と反復本体をネイティブの音声クロックへ予約し、通常対局→終盤も原稿の拍へ接続する。
BGM音量・SE音量・消音・演出時のduckを別々に適用する。重要SEの優先と音量補正、
報酬SEの和音別音源を維持し、SEだけ高域シェルフ-6dB/1400Hzと3200Hzの非共振ローパスを通す。
撃破・バトルパスなど既存の合成音は`tools/prepare-native-aux-audio.mjs`でPCMへ事前出力する。
動画は映像だけWebKitで流し、同梱動画の音声をネイティブへ分離する。短縮再生でも音程を維持する。
待機中のBGMのPCMは解放し、報酬音源は24種類、動画音声は2本、同時SEは8音＋動画2音に制限する。

停止位置と再開意図はiOS側で保持する。`SceneDelegate`から非アクティブ時の停止と
復帰時の再開を直接呼び、WebKitのメディア停止解除の完了やJavaScript通知を待たない。
遅れて届いたWeb側の背景停止要求は、復帰済みのBGMを再び止めない。
実機では背景中に通常の音声割り込みが入り、復帰時に終了通知が届かない順序も確認した。
この背景中の割り込みに限り、前面復帰時にiOSの音声セッションを再有効化できた場合に解除する。
前面で始まった着信や、ほかの音声・手動再開の指定は維持する。JavaScript側もネイティブの
再開結果を待って停止状態を解除し、古い割り込みフラグで復帰確認を省略しない。
通常の曲変更・明示停止・消音と、着信中/着信後の再開可否は引き続き尊重する。
ブラウザー版とAndroid版は従来のWeb Audio経路を使う。
1:08・1:22付近の旋律調整案は`reports/home-default-melody-20261028/`に比較用として保存し、
指定音源を基準にするという本人の追加指示に従って、本番の標準曲には適用していない。
3曲の採用記録と編集位置は`docs/home-phase-bgm-choices.json`、元の採用音源とループ原本は
`assets/audio/masters/home-phase-*-approved-20261024.m4a`と
`home-phase-*-loop-20261024.m4a`へ保存する。
`tools/apply-home-bgm-choice.py`は音源再生成後も標準曲を含む4曲の原本とループ位置を再適用する。
選曲機能そのものは音源を加工せず、各曲の指定された原本を再生する。

`tools/check-home-phase-bgm.mjs`で背景・本人の選択・進行同期・専用曲との分離を、
`tools/check-home-music-settings.mjs`で保存・復元・既存音量の維持・設定UIを、
`tools/check-adaptive-music.mjs`で反復と背景停止・続き再生を確認する。
`tools/check-native-home-music.mjs`でiOS向け経路の切り替えと音量・消音・復帰を、
`tools/check-native-home-render.mjs`で標準曲の出力と原音を照合する。
`npm run check:audio:ios`では全19曲のループ・186ファイルのSE・高音抑制・重要SEの優先と
ネイティブ復帰を本番Swiftコードで検証する（macOS/Xcodeが必要）。
`node tools/build-ios-audio-repro.mjs`は`ios:sync`後に同じplayerを使う診断HTMLを生成する。
別のアプリIDで署名したDebug版を`--audio-repro`付きで起動し、端末上のアプリ切り替えと
`TOTTERY_AUDIO_TRACE`・`AUDIO_REPRO_STATE`で位置と状態を照合できる。診断HTMLは配布同期で除去する。

## 解放条件

| 装飾 | 対応するフォイル        |
| ---- | ----------------------- |
| 土   | 2・3のいずれか          |
| 海   | 4・5のいずれか          |
| 森   | 6・7のいずれか          |
| 氷   | 8・9のいずれか          |
| 空   | 10                      |
| 天界 | 天使のJ・Q・Kのいずれか |
| 魔界 | 悪魔のJ・Q・Kのいずれか |

入手経路は問わず、すでに持っているフォイルも対象。装備・王への指定は不要。
`areaRewardsFor`と対応を共有する。Aのフォイルはこの7エリアには対応しない。
未解放でも見本と条件を確認できるが適用できない。標準は常に使用可能。

土・海・森・氷のキャラも、2〜9それぞれの所持フォイルと対応する。
3のみ所持なら女性ゾンビ、6のみなら男性エルフなど、獲得した本人を表示する。
そのエリアの2キャラを所持していれば好きな方を選べる。
天界・魔界のキャラは、所持するJ・Q・Kそれぞれのフォイルと対応する。
Jだけ所持していればJ、QだけならQを表示し、未所持のKを使用できない。
複数を所持している場合は、着せ替え画面の「ホームに迎えるキャラ」で選べる。
全15キャラに、風景とキャラを一枚に描いた横長のホーム専用挿絵を使う。
承認済みの7枚（土2・海4・森7・氷9・空10・天界K・魔界K）はそのまま使用する。
残り8キャラは、各エリアの承認済み構図と光に合わせた専用イラストを使う。
カード用の縦長イラストを拡大して代用しない。ホーム本体・着せ替え見本・サムネイルで同じ挿絵を参照する。
背景とフレームはエリアで共通。キャラの名前もイラストに合わせる。
選んだキャラは`collection.homePortraits`にエリアごとに保存する。
一度決まったキャラは、別のフォイルを獲得しても勝手に変更しない。

獲得時は自動変更せず、本人が選んだ装飾だけを`collection.homeTheme`に保存する。
選択は現在のスキン所持情報と同じ端末の保存領域を使う。通貨・所持品・獲得結果は
変更しない。保存時も最新の所持状態を再確認する。未獲得や不正な選択は標準へ戻す。
最後のフォイル1枚は既存仕様で分解できないため、所持情報から解放を判定する。

## 表示・検証

ホームの着せ替え専用ボタンは置かず、右上の設定または自分のプレイヤー情報から開く。
プレイヤー情報とお知らせは同じ段に配置し、通貨・チケットは残高バーにまとめる。
対戦ボタンの下に各メニューを2列で並べ、イラストは横長の全景を維持する。
ホーム本体は動的ビューポートの高さに固定し、ページをスクロールさせない。
ヘッダーの実際の高さを除いた残りへ配置し、下の安全領域はホーム内で一度だけ確保する。
標準ホームはイラストの空きを残さず、2列3段のメニューを広げて画面を使う。
着せ替えホームでは高さが足りない分だけ挿絵を縮め、全景と操作ボタンを残す。
小型画面ではアイコンと文字を横並びにし、ボタンの押せる高さを44px以上確保する。
ホーム以外の画面とダイアログ内部のスクロールは制限しない。

ダイアログは一覧だけスクロールし、上部の閉じる・下部の戻ると適用は常時表示する。
装飾画像・四隅・縁は操作を遮らず、文字の背景に不透明なパネルを敷く。
`assets/skins/home-v1/`のWebP22点（`characters/`内の追加8点を含む）とSVG21点を通常のビルドで配布する。

`tools/check-home-themes.mjs`でフォイルの対応、未獲得制限、保存・復元、通貨の保持、
獲得時の自動切替がないことを確認する。画面はスマートフォンの幅で別途確認する。
