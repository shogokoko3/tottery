### 称号の名前

札の**動きをそのまま名乗る**形にしてある。縦横と斜め、偶数と奇数が名前の上で対になるので、
規則を覚える助けにもなる。ここを崩すときは13個まとめて考え直すこと。

A 乱世の奇手 / 2 一歩の堅陣 / 3 斜影の一歩 / 4 双進の勇 / 5 双斜の勇 /
6 偶進の理 / 7 偶斜の理 / 8 奇進の理 / 9 奇斜の理 / 10 跳躍の妙 /
J 縦横無尽 / Q 斜貫無尽 / K 王道無双
通し: 十三道の使い手(13種すべて80回) / 盤上無双(すべて500回)

## 3. 決まりごとと、その理由

**理由を消さないこと。** 数字だけ見ると「もっと気前よくしていいのでは」と思えるが、
どれも一度考えた末にこうしている。

### 3-1. 王に選んだ札だけが貯まる（本人の決め）

はじめは「指した手すべて」を数えていたが、本人の指示で**王に選び、王として動かした回数**に変更した。
1局で育つのは1種類だけになる。

- 王位の継承(2・3が倒れたとき)で継ぐのは**同じ数字**なので、途中で王の札が変わることはない
  （`src/game/reducer.js` の「王位を継承」）。だから `mover.rank` をそのまま使ってよい
- **未解決の懸念**: この数え方は「貯めるために王を動かす」誘因を生む。王を動かすのは本来危険な手なので、
  称号のために不利な手を指す人が出るかもしれない。恩恵が見た目だけなので実害は小さいが、
  遊んでみて気になるなら「1局につき+1」に寄せる案がある（本人にも伝達済み）

### 3-2. 1局で数えるのは3回まで（`MASTERY_PER_GAME`）

歯止めが無いと「**わざと長引かせて同じ札を動かし続ける**」のが一番効率のいい遊び方になり、盤がつまらなくなる。

### 3-3. 段は5つ、500回で頭打ち（`MASTERY_STEPS`）

青天井にすると、1000局遊んだ人と100局遊んだ人の差が**永久に開き続け**、あとから始めた人が追いつけない。
「やり込んだ人が報われる」と「新しい人が追いつける」は、上限を置くことでしか両立しない。

### 3-4. 恩恵は見た目だけ。盤には効かせない ← **最重要**

当初「熟練度の高い札が必ず1枚配られる『印』」の案があったが、**本人が取り下げた**。

再び盤に効かせたくなったときは、**先に塞ぐべき穴が2つある**。

1. **配り札は片方の端末が決めて、相手はそれを信じている**
   `src/game/actions.js` の `enrichAction` が `START_SETUP` のときに1回だけシャッフルし、
   その**結果の配列そのもの**を相手に送る。受け取る側は形しか見ない（`reducer.js` の `deckOk`）。
2. **装備の所持を誰も検証していない**
   `src/game/areas.js` の `sanitizeLoadouts` は型と文字列長しか見ない。`src/server/verify-match.js` にも検証はない。

この2つがある状態で盤に効く恩恵を足すと、**改造した端末が「熟練度カンスト」を名乗って毎局好きな札を引ける**。
持ち点は一度汚れると巻き戻せない。

`check-mastery.mjs` の最後の節が、`board.js`・`reducer.js`・`actions.js`・`areas.js` に
`mastery` の語が出てこないことを見張っている。**うっかり盤に効かせたら検査が落ちる。**

### 3-5. 称号は `unlocked(p)` 方式＋焼き付け

`profile.mastery` から毎回判定する（一覧に自動で並ぶ）。届いた瞬間に `profile.titles` へも焼き付けるので、
以後は熟練度の数字が無くても名乗れる。持ち点の称号と同じ作り。

## 4. 残っている作業

### A. アイコン（段5＝500回で解放）— 素直にできる

`src/game/icons.js` の `ICONS` に13個足す。所持判定は同ファイルの `hasIcon(profile, id)`。
いまは `free` / `titleId`（称号連動）/ `profile.icons` の3通りしか見ないので、
**`icon.mastery = { rank: "J", need: 500 }` のような条件を1つ足す**のが素直（`MASTERY_ICON_STEP` が既にある）。

### B. アイコンフレーム — **仕組みから作る必要がある**

いまフレームは**1種類しかなく、文字列直書き**で出している。
`src/game/season.js` の `SEASON_FRAME = "gold-laurel"` を、
`src/ui/playericon.jsx` が `frame === "gold-laurel"` と**直接比較**して月桂冠を描いている。

つまり「フレームの台帳」も「解放条件の表」も存在しない。熟練度フレームを足すなら、

1. フレームの台帳（id・見た目・解放条件）を新設する
2. `playericon.jsx` を id で引く形に直す（`gold-laurel` も台帳へ移す。**既存の所持者を失わせないこと**）
3. 検査を足す

予定していた条件: 13種すべてが段3 → フレーム1つ / すべて段5 → 最上位のフレーム。

### C. 「印」（盤の効果）— 保留

本人が取り下げた。再開するなら §3-4 の穴を塞ぐのが先。
そのうえで、釣り合いは議論ではなく**実測**で決める（エリアの相性表を出したときと同じやり方で、
「印あり vs 印なし」を数千局回し、勝率差が±1%以内に収まらなければランク戦に入れない）。

## 5. 落とし穴（実際にはまったもの）

- **CSS が2つある。** `src/styles.css` と `src/ui/title-frame.css`。
  `screens.jsx` の `<style>` で **`TITLE_STYLES` が後に連結される**ので、同じ強さなら title-frame.css が勝つ。
  片方だけ見て直すと打ち消される（称号の「取得済み/未取得」の見分けが消えたのがこれ）。
- **CPU の手も `y()` を `__foe` 無しで通る。** 相手の手だけなら `__foe` で弾けるが、CPU は弾けない。
  **駒の持ち主 `mover.owner === mySeat` を必ず見ること。**
- **`title-design.js` に意匠が無い称号は、黙って「素朴」に落ちる。** 検査は通ってしまうので気づけない。
  称号を足したら意匠も足す。
- **共有の作業ツリー。** 複数セッションが同じ repo を同時に触る。`git add -A` は使わず、
  自分が触ったパスだけを指定する。`admin.html` は手元だけなので stage しない。
- **`npm run check` への登録を忘れない。** 別セッションが古い写しから編集して、登録行が消えたことがある。
  push 前に `grep check-mastery package.json`。
- **`tools/check-replay.mjs` が稀に落ちる**（`9×9: 自動配置の枚数が合わない`）。熟練度とは無関係の既知のぐらつきで、
  別タスクとして切り出し済み。全体検査が1回落ちたらこれを疑う。
